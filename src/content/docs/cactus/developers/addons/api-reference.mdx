# API Reference

This section provides a comprehensive reference for the Cactus addon API, including all interfaces, classes, and methods you'll need to develop addons.

## Core Interfaces

### ICactusAddon

The main interface that all addons must implement.

```java
public interface ICactusAddon {
    void onInitialize(RegistryBus registryBus);
    void onLoadComplete();
    void onShutdown();
}
```

#### Methods

- `onInitialize(RegistryBus registryBus)`: Called when the addon is initialized. Use this method to register your content with the Registry Bus.
- `onLoadComplete()`: Called when all addons have been initialized. Use this for any post-initialization logic.
- `onShutdown()`: Called when Cactus is shutting down. Use this to clean up resources.

### RegistryBus

The central registry system for addon content.

```java
public class RegistryBus {
    public <T> void register(Class<T> type, Function<RegistrationContext, T> factory);
    public <T> void register(Class<T> type, BiConsumer<List<T>, RegistrationContext> consumer);
    public <T> void completeAndTake(Class<T> type, BiConsumer<T, Addon> callback);
    public <T> void completeAndTake(Class<T> type, Consumer<T> callback);
    public <T> void take(Class<T> type, BiConsumer<T, Addon> callback);
    public <T> void take(Class<T> type, Consumer<T> callback);
    public <T> List<T> request(Class<T> type);
    public <T> void complete(Class<T> type);
    public Addon getOwner(Object o);
}
```

#### Methods

- `register(Class<T> type, Function<RegistrationContext, T> factory)`: Register a single instance of the specified type.
- `register(Class<T> type, BiConsumer<List<T>, RegistrationContext> consumer)`: Register multiple instances of the specified type.
- `completeAndTake(Class<T> type, BiConsumer<T, Addon> callback)`: Complete the specified type and call the callback for each registered instance.
- `completeAndTake(Class<T> type, Consumer<T> callback)`: Complete the specified type and call the callback for each registered instance (without addon information).
- `take(Class<T> type, BiConsumer<T, Addon> callback)`: Call the callback for each already completed instance of the specified type.
- `take(Class<T> type, Consumer<T> callback)`: Call the callback for each already completed instance of the specified type (without addon information).
- `request(Class<T> type)`: Get all completed instances of the specified type.
- `complete(Class<T> type)`: Manually complete the specified type.
- `getOwner(Object o)`: Get the addon that owns the specified object.

### RegistrationContext

Provides access to services and handlers during content registration.

```java
public class RegistrationContext {
    public <T> T require(Class<T> serviceClass);
    public void bind(Class<T> serviceClass, T instance);
}
```

#### Methods

- `require(Class<T> serviceClass)`: Get an instance of the specified service class.
- `bind(Class<T> serviceClass, T instance)`: Bind an instance to the specified service class.

### Configuration Files

Custom settings and data storage.

#### Base Class

```java
public abstract class FileConfiguration<T extends FileConfiguration<T>> {
    public FileConfiguration(String name, ConfigHandler handler);
    public void init();
    public void filePreprocess(File file);
    public abstract JsonObject toJson(TreeSerializerFilter filter);
    public abstract T fromJson(JsonObject object);
    public File getFile(File directory);
    public boolean isFirstInit();
    public void wrappedInitialize();
    public Map<Class<?>, FileConfigurationWrapper<?>> getSubConfigurations();
}
```

#### Example

```java
public class MyConfig extends FileConfiguration<MyConfig> {
    public MyConfig(ConfigHandler handler) {
        super("myConfig", handler);
    }
    
    @Override
    public void init() {
        mainGroup.add(new BooleanSetting("enabled", true));
    }
    
    @Override
    public JsonObject toJson(TreeSerializerFilter filter) {
        JsonObject json = new JsonObject();
        json.addProperty("enabled", mainGroup.get("enabled").get());
        return json;
    }
    
    @Override
    public MyConfig fromJson(JsonObject json) {
        if (json.has("enabled")) {
            mainGroup.get("enabled").set(json.get("enabled").getAsBoolean());
        }
        return this;
    }
}
```

## Annotations

### @ContentPackDependent

Marks a class as dependent on a specific content pack.

ContentPackManager.get().isEnabled(MyFeature.class);

## Settings

Settings are the building blocks of configuration in Cactus addons. They provide user interface elements for modifying configuration values and persisting them between sessions.

### Setting Interfaces

#### ICopyable

Interface for objects that can be copied.

```java
public interface ICopyable<T> {
    T copy();
}
```

#### IMutableVisibility

Interface for objects with mutable visibility.

```java
public interface IMutableVisibility<T> {
    boolean visible();
    T visibleIf(BooleanSupplier supplier);
    
    static void all(BooleanSupplier supplier, IMutableVisibility<?>... instances) {
        for (IMutableVisibility<?> instance : instances) {
            instance.visibleIf(supplier);
        }
    }
}
```

## Examples

### Complete Addon Example

```java
@CactusAddon(modId = "myaddon") // this is only required for NeoForge platform support
public class MyAddon implements ICactusAddon {
    
    @Override
    public void onInitialize(RegistryBus registryBus) {
        // Register modules
        registryBus.register(Module.class, ctx -> {
            List<Module> modules = new ArrayList<>();
            modules.add(new MyModule1());
            modules.add(new MyModule2());
            return modules;
        });
        
        // Register commands
        registryBus.register(Command.class, ctx -> {
            List<Command> commands = new ArrayList<>();
            commands.add(new MyCommand1());
            commands.add(new MyCommand2());
            return commands;
        });
        
        // Register HUD elements
        registryBus.register(HudElement.class, ctx -> new MyHudElement());
        
        // Register content pack
        registryBus.register(ContentPack.class, ctx -> new MyContentPack());
        
        // Register configuration
        registryBus.register(FileConfiguration.class, 
            ctx -> new MyConfig(ctx.require(ConfigHandler.class))
        );
        
        // Register placeholders
        registryBus.register(PlaceholderRegistration.class,
            new PlaceholderRegistration("myValue", new PlaceholderHandler.StaticPlaceholderValue(
                () -> "Hello World!", // value resolver
                "Fallback", // fallback if the resolved value is null, or the resolver throws an exception
                () -> true // condition for your placeholder to be resolved
            ))
        );

        // Register a placeholder mapper
        registryBus.register(PlaceholderMapperRegistration.class,
            new PlaceholderMapperRegistration<>(String.class, "reverse", 
                (input, function) -> new StringBuilder(input).reverse().toString()
            )
        );
    }
    
    @Override
    public void onLoadComplete() {
        // Called when all addons have been initialized
        System.out.println("My addon loaded successfully");
    }
    
    @Override
    public void onShutdown() {
        // Clean up resources
        System.out.println("My addon shutting down");
    }
}
```

### Command with Subcommands Example

```java
public class MyCommand implements Command {
    @Override
    public String getName() {
        return "mycommand";
    }
    
    @Override
    public void build(LiteralArgumentBuilder<SharedSuggestionProvider> builder) {
        // Subcommand 1
        builder.then(literal("sub1")
            .executes(context -> {
                ChatUtils.info("Subcommand 1 executed");
                return 1;
            }));
        
        // Subcommand 2 with argument
        builder.then(literal("sub2")
            .then(argument("value", StringArgumentType.string())
                .executes(context -> {
                    String value = StringArgumentType.getString(context, "value");
                    ChatUtils.info("Subcommand 2 executed with value: " + value);
                    return 1;
                })));
    }
}
```

## Migrating from v1 to v2

If you're migrating from Cactus Addon API v1 to v2:

1. **Update entrypoint**: Change from `CactusAddon` to `ICactusAddon`
2. **Update imports**: Update imports to use the v2 package structure
3. **Use Registry Bus**: Replace direct manager access with Registry Bus registration
4. **Update settings**: Update settings to use the new setting system
